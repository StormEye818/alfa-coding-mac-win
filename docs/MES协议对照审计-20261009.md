## 一、为什么这次踩坑（直面问题）

**MES 字符串库明明有官方配方（ATFCSH/ATFCSD/ATFCSM/ATCFC 流控全家桶），我们却在代码里写了个 `ATSW00`——一个 MES 根本不用、甚至可能根本不存在的命令。** 根因是流程性的：

1. **情报利用不系统**：拿到字符串库后只"按需摘抄"（修协议号时摘了 ATSP7 一条），从未做过**命令集级的全面对照**；
2. **没有协议白名单约束**：实现里可以自由发明 AT 命令，而山寨适配器对**任何命令都回 OK**，把臆造命令"洗"成了看似正常；
3. **模拟车失真**：沙箱不校验协议语义（不等流控、对命令照单全收），把两类错误全部掩盖。

**制度建议（重要）**：AT/UDS 层只允许使用字符串库出现过的命令与序列（白名单）；任何新命令必须注明"库中未见"并真机验证。本报告的 gap 清单即首份白名单对照表。

## 二、MES 官方协议全貌（从字符串库复原）

### 2.1 初始化模板（多命令串，按平台分组）

CAN 29 位（FCA/Giulia 主用）：

```
ATE0\rATL0\rATH0\rATS0\rATAL\rATCP18\rATCRA18DAF1…   ← 主力模板（3736/52388/52616）
ATE0\rATL0\rATH0\rATS0\rATAL\rATAT0\rATST22\rATCRA…   ← 变体：带定时控制（52572）
ATE0\rATL0\rATH0\rATS0\rATAL\rATAT0\rATST26\rATCRA…   ← 变体：ST26（52540）
```

操作级模式切换（**每个操作单独设置**，不是一次性初始化）：

```
ATCAF1\rATAT1          （格式化读，52412）
ATCAF0\rATAT0\rATST20  （原始读，52416）
ATCAF1\rATAT0          （52556）
ATCAF0\rATAT0\rATST03  （52560，快超时）
ATCAF0\rATAT0\rATST10  （52600）
```

K 线/其它平台另有 `ATIB48/ATIB10/ATIIA/ATTP3/4/5/H`、`ATSH81`、`ATSP4/5/6` 等（本车用不到，略）。

## 三、Gap 清单（按风险排序）

### 🔴 P0 — 实车直接受影响

**#1 流控配置未对齐官方（本次实车故障的直接原因）**
- 现状：手动 FC 注入 + ATCFC0（自研路径）；沙箱已按真车语义验证（61/61）
- MES：ATFCSH/ATFCSD `30 00 00`/ATFCSM/ATCFC1（ELM 内建流控）
- 风险：手动 FC 在真 ELM 时序下仍属"未经真机验证"（FC 发送引出的假提示符已做排水容错，但 ELM 对中途写入的行为未实测）
- 建议：**双轨并行**——保留手动 FC 为兜底，同时按 MES 配方下发 ATFC 全家桶（用适配器内建流控），下轮真机用日志按钮判定哪条真正生效

**#2 125k 舒适总线协议映射错误（对齐阶段会翻车）**
- 现状：125k 节点映射 ATSP9（=29 位 250k！）——**协议号是错的**
- MES：非标速率用 USER 协议（ATSPB/ATSPC + ATSPA 参数编程）
- 影响：PROXI 对齐扫到 41 个 125k 舒适总线节点时可能全部失败
- 建议：照抄 MES 的 ATSPA/ATSPB/ATSPC 参数（字符串库里有 `ATSPA7` 线索，需挖完整参数串），或采用探测阶梯

### 🟡 P1 — 可靠性/兼容性

**#3 AT 命令集缺口：ATAL / ATCP18 / ATAT / 逐操作 ATST**
- ATAL（长消息）与 ATCP18（29 位优先级）出现在**每条** CAN-29 模板里——某些适配器（含 vLinker 固件）可能依赖它们正确收发长帧/正确优先级
- ATST 逐操作调参（快操作 ST03、慢 ECU ST99/FF）——我们固定 ST32=200ms，慢 ECU 可能超时
- 建议：初始化模板照抄 `ATE0 ATL0 ATH0 ATS0 ATAL ATCP18`（+ATCRA），操作级按 MES 加 ATAT0/ATSTxx

**#4 安全访问种子格式存疑**
- 我们：`27 03` 取种子 / `27 04` 送密钥（5 位 PIN BCD）
- MES 证据：`0C 57 01 01 10 61 24 A7 1D 08 2D FF 40`——**27 01** 路径 + **11 字节种子**（`57 01 01…`）
- 风险：写受保护 DID（如安全相关）时 27 03/04 可能是错的服务号
- 建议：实车日志验证 27 交互；必要时按 MES 的 27 01/02 长种子算法实现（库内有种子样例可比对）

**#5 协议探测阶梯 vs 固定 ATSP**
- MES：先探测（Checking 29/500…）再锁定；我们直接 ATSP7
- 好消息：ATSP7 与 MES 主用一致；风险在非常规场景（改装网关、不同总线时序）
- 建议：连接失败时回退到探测阶梯（低优先）

### 🟢 P2 — 一致性/仿真度

**#6 模拟车 PROXI 头与实车不同**：实车 DATA1 头 `06639064587OUTPUT-SIT #…`，我们 Mock 用 `406200000001OUTPUT-SIT %`——逻辑不解析头部故无害，但影响"仿真度"，建议按实车样例更新
**#7 ELM 可编程参数（AT PP 2C/2D）**：MES 会改写 ELM 内部参数（SV 81/0A/01），我们从未动过——clone 适配器通常不支持 PP，属"可忽略差异"，但遇到原装 ELM 可能行为不同
**#8 OBD 模式 09（VIN/标定号）等附加读取**：MES 有、我们无——不影响刷写主流程，功能增强项

## 四、逐项对照速查

| 流程 | MES | 我们 | 判定 |
|---|---|---|---|
| 初始化 | ATE0/ATL0/ATH0/ATS0/ATAL/ATCP18/ATCRA | ATE0/ATL0/ATS0/ATH1/ATCAF0/ATSP7/ATST32/ATCFC0 | ⚠️ 缺 ATAL/ATCP18/ATAT，ATH 策略不同 |
| 寻址 | ATSH+ATCRA（+ATCP18） | ATSH+ATCRA+状态重申 | ⚠️ 缺 ATCP18；状态重申是我方加固 |
| 单帧读 | 03 22 xx xx（含 PCI） | 同 | ✅ |
| 多帧读 FC | ATFC* 配置内建流控 | 手动 FC 注入 + ATCFC0 | ⚠️ 待真机判定 |
| 多帧写 FC | 解析 FC（BS/STmin） | 同 | ✅ |
| 写 PROXI | 2E 20 23 <DATA1> | 同 | ✅ |
| 写后校验 | 22 10 2A + 重读 22 20 23 | 同 | ✅ |
| CRC | 数据自带 CRC 区 | CRC-16/KERMIT 封缄 | ✅（实现独立但对齐） |
| 超时 | ATST 逐操作（03~FF） | 固定 ST32 | ⚠️ |
| 自适应定时 | ATAT0/1 逐操作 | 未控制 | ⚠️ |
| 安全访问 | 27 01 长种子（样例） | 27 03/04 PIN BCD | ❓ 待实车核对 |
| 错误处理 | NRC 解析（7F …） | 同 | ✅ |
| 探测 | 速率探测阶梯 | 固定协议 | ⚠️（fallback 缺失） |

## 五、结论

- **本次踩坑 = 情报利用不系统 + 可发明命令 + 模拟失真** 三连。核心读写语义（PCI 帧格式、22/2E 服务、102A 校验、CRC）我们与 MES 是**一致**的——差距集中在**适配器配置层（AT 词汇表）**与**操作级参数**。
- 最优先修：**#1 流控双轨对齐**、**#2 125k 协议映射**、**#3 ATAL/ATCP18/ATST 补齐**（均为低风险小改动）。
- 请评审后决定修复范围；修复时按"白名单对照"逐条落，并保留日志按钮做真机判定。
