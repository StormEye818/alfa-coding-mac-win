## 4. 移动端借鉴（来自 Multiecuscan 2.7.3 iOS IPA，2026-11-18）

### 4.1 它的「不选接头」真相（①级：元数据 + 字符串堆）

- **并非完全不选**：用户仍选一个「连接方式大类」（WiFi / 蓝牙 / BLE），但**具体设备、端口、波特率、针脚线全自动**。「不用选接头」的实际体验来自 vLinker MS / CANtieCAR 的**多 CAN 通道自动切换**，免物理换线。
- MFi 自动发现：`Info.plist` 声明 `UISupportedExternalAccessoryProtocols = [com.obdlink, com.vgatemall]`；字符串堆有完整流程 `Searching for Bluetooth Accessory` → `Accessories:` → `OBDLink bluetooth accessory found` / `Vgate vLinker MS ... found`。即 `EAAccessoryManager.connectedAccessories` 枚举 + 协议串过滤，**无需扫描等待**。
- 另两路：BLE（`Searching for Bluetooth BLE devices` / `BLE write/read characteristic:`）、WiFi（`Searching for OBDLink/Vgate WiFi devices`、CANtieCAR `35000` → `192.168.4.1:23`）。
- 三路统一汇入同一个 ELM AT 层（`WriteStringToEASession` / `WriteStringToNetSocket` / `WriteStringToBLEPeripheral` → `SendCommandToELM`），这是最值得抄的架构点：**传输可替换，协议层不动**。
- 优先级 MFi→BLE→WiFi 只有 ②级（字符串顺序 + MFi 被系统独占、BLE 扫不到的机制推断）；超时的具体毫秒与重连上限 ③级（引用程序集方法体为空壳），**不许照抄数值**。

### 4.2 我们移动端已经有的底子（无需重写）

- `mobile/src/mobile-bridge.js:360-432` `listPorts()` 已把 MFi 置顶 + BLE 扫描；`open():330-351` 已支持 `ea:` / `ble:` / `spp:` / `tcp:` 四种。

- `mobile/ios/App/App/Info.plist` 已声明 **16 个**（不是 17）MFi 协议串，含 `com.obdlink` / `com.vgatemall`，比 MES 的 2 个更全。

### 4.4 不建议照搬

- MFi 私有协议串：`com.obdlink` / `com.vgatemall` 需厂商授权/认证；真机能枚举 ≠ 能上架，未授权串有审核风险。我们已声明 16 个，不要继续扩张。
- 私有 AT 扩展（`VTSET_CAN` / `ATMC`）是厂商固件配合，保持现在的「回 `?` 容忍」即可，不宣称官方兼容。
- MES 的 IAP 收据校验、DLV/CALCSKV 服务器校验、诊断报告上传——**不抄**（无必要 + 隐私/合规）。
- 超时/重连次数无 ①级证据，按猜测值实现等于编造行为。

### 4.5 UX 对比结论与最值得先做的三项（收益 ÷ 代价）

移动端 MES 与桌面 5.5 **同源数据库**（IPA 带 `data01/02/03/05.dat` 约 78MB + 多语言包），主流程 Make→Model/Version→System→Module→连接后固定 5 tab（Info/Errors/Parameters/Actuators/Adjustments）。相对桌面裁剪的是独立字节编辑器、本地 PDF 报表（改 Send Report 上传）、免费版 20 分钟 + 4 参数闸门。相对 alfaproxi 它多了全品牌、Simulate 免硬件演示、整车 Scan 自动识别、参数置顶/排序/模板；alfaproxi 反而**超出**它的有字节编辑器、按位图逐节点精确对齐、iPad 双屏。

按收益/代价排序：

| 优先 | 借鉴项 | 我方源文件 | 代价 |

| 1 | 连接方式收敛成粗类别 + 设备自动发现 + 直连（见 M1–M4） | 根 `app/app.js:138,486`；`app/mobile-ui.js:224,334` | 低-中 |

## 6. 执行编排与验收口径（2026-11-18 开工版）

### 6.1 唯一验收标准（等同 porsche-coder 项目）
1. **字节级对齐处必须全 A**：凡有 MES ①级行号证据的项，实现结果必须与 MES 语义逐字节/逐判定一致；`align-mes` 全 A、退出码 0。
2. **拒绝假绿**：门禁必须真执行被测行为（跑函数/发帧/断言输出），不许只查「文件存在 + 字符串命中」；每条断言要有可注入的反例证明它会红。
3. **退出码三态**：`0`=全 A；`2`=仅前置未满足（未构建/未连接等，未判内容）；`1`=其它一律真缺陷。
4. **逐字节确定性**：同一 HEAD 连续多次运行输出逐字符相同，sha256 一致；本机与干净 clone 一致。
5. **不可结案词**：「包内没有 / 需上车 / 运行时态 / 与 MES 同界 / 源包限制 / 承诺外」不得作为结案理由，只能作为待挖线索并附下一载体。
6. **③级扩展不许冒充对齐**：扩展自身正确不算对齐证据，必须在报告里单列。
